# Отчет по лабораторной работе: Внедрение CI в проекты по информационной безопасности

## 1. Что такое CI?
**CI (Continuous Integration)** — это практика разработки программного обеспечения, которая заключается в постоянном слиянии рабочих веток разработчиков в общую основную ветку. 

Этот процесс сопровождается **автоматическим запуском сборок и тестов**, что позволяет обнаруживать ошибки интеграции на самых ранних этапах. Вместо того чтобы проверять код вручную перед релизом, система делает это автоматически при каждом изменении.

---

## 2. Зачем CI нужен в ИБ-проектах?
В проектах, связанных с информационной безопасностью, CI выполняет роль «автоматического фильтра», который не пропускает уязвимый код в продакшн:

* **Автоматизация поиска уязвимостей (SAST):** Сканеры (например, Bandit для Python или Semgrep) проверяют код на наличие небезопасных конструкций при каждом коммите.
* **Контроль зависимостей (SCA):** Автоматическая проверка используемых библиотек на наличие известных уязвимостей (CVE).
* **Секреты в коде:** CI-пайплайны могут искать забытые API-ключи, пароли или токены, предотвращая их попадание в открытый доступ.
* **Целостность:** Гарантия того, что итоговый бинарный файл или образ собран в чистой среде и не был модифицирован злоумышленником вручную.

## 4. Запуск GitHub Actions
### Описание
Для проекта был настроен Workflow в GitHub Actions. При выполнении команды `git push` триггер запускает контейнер, в котором:
1. Подготавливается окружение.
2. Проверяется синтаксис и стиль кода.
3. Проводятся тесты безопасности.
